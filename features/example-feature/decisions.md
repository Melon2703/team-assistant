# Decisions — `<Название фичи>`

> Архитектурные / GD / scope решения по этой фиче, влияющие на нарезку задач и анализ прогресса.
> Skill `feature-decomposition` читает этот файл перед декомпозицией, чтобы не включать в задачи
> то, что уже решено иначе (пример: «spine делает аниматор — не включать в задачи программистам»).
>
> Датированные фиксации оценок (`feature-weekly-state` с «зафиксируй») тоже сюда.

## Формат

```
### YYYY-MM-DD — <название решения>

- **Decision:** что решено
- **Owner:** кто принял
- **Context:** на основании чего (Slack-тред / встреча / ТЗ)
- **Влияние на нарезку:** что это меняет при заведении задач
```
